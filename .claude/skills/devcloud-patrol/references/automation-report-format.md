# 自动化回复统一格式（表格）

本文件是 `devcloud-patrol` 下**所有 BB 自动化**（DB 存储巡检、Worktree 巡检、每周系统盘复盘等）
面向 owner 的**回复格式唯一契约**。规则来源见 [storage-rules.md](storage-rules.md)；
worktree 的对象级内容契约见 [worktree-report-format.md](worktree-report-format.md)。
本文件只定义「发出去的那段回复长什么样」，不重复判定规则。

## 原则

1. **回复整体用表格**：owner 收到的消息以 Markdown 表格为主体，不写长段散文。
2. **一屏优先**：先给一张汇总表，再给按结论分组的明细表；每项一行。
3. **结论跟证据走**：每个对象必须能在一行内讲清「谁的、多老、多大、为什么这样处置」。
4. **机器可读证据另存**：JSON/raw 落本轮专属目录，回复里只给路径链接，不贴原始输出。
   **所有自动化一律不产出 HTML**（owner 2026-09-18）：DB、Worktree、每周复盘都不写
   `report.html`；需要图文材料时由 owner 单独一次性要求，不写回流程默认值。
5. **跨轮同口径**：年龄 = now − 创建时间（worktree 用 `.git` mtime）；上次活跃时间 =
   树内最新文件 mtime（卷/worktree）/ `Last used`（构建缓存）/ 镜像「不可得」。
   两者都写绝对时间戳，不写「N 天前」。

## 标准结构（按任务类型裁剪章节，顺序固定）

### 1. 汇总表（必给）

| 指标 | 值 |
|---|---|
| 本轮清理 | N 个 / X GB（口径注明，如「候选口径」） |
| 实际回收 | Y GiB（用 `df -h` 前后差） |
| 卷/对象总数 | A → B |
| 不清理 | M |
| 需决策 | K |

表下紧跟一行结论汇总：`已清理 N · 不清理 M · 需决策 K`（数字口径与明细表一致）。

### 2. 对象明细表（清理与未清理共用同一形状）

**固定列（owner 2026-09-18 定稿）：`所属项目 | 清理结果 | 原因 | 空间 | 年龄 | 上次活跃时间`**

- `所属项目` = 拥有该对象的仓库/项目（worktree 用 `repo`，卷/镜像用归属项目；归属未确认时
  写「未确认」并给已排除候选）。**不允许留空或只写「无主」。**
- `清理结果` 只能取：`已清理` / `自动清理（本轮）` / `不清理` / `需决策`。原因不再塞进这一列。
- `原因` = 判定依据；`不清理`/`需决策` 必填（用 storage-rules.md 的固定词表），`已清理` 写
  远端证明（PR/MR 链接或远端分支）。
- `空间` = 表观字节（回收前 `du -sbx` 或卷/镜像大小）。
- `年龄` = now − 创建时间（worktree 用 `.git` mtime 口径，写 `xx.x d`）。
- `上次活跃时间` = **有就给时间戳**：卷/worktree 用树内最新文件 mtime（worktree 为
  `du -sbx --time` 口径）；构建缓存用 BuildKit `Last used`；镜像不记录 last-used，写「不可得」。
  取不到一律写「不可得」，不得用年龄或创建时间代替。
- 因未到期不清理的，在 `原因` 里写 `MM-DD HH:MM 起自动清理`。
- 已清理与未清理各按 `空间` 降序；同源批次可合并为一行（注明数量），但必须保留所属项目、
  年龄区间、合计空间、结论。
- worktree 表最多 30 行（其余见 `evidence.json` 的 `unreclaimed[]`）；DB 表逐项列全。

### 3. 不清理 / 需决策表

- 与上表同列同形状，按 `清理结果` 分组；`需决策` 项**逐项一行**，必须给出
  **所属项目 + 证据 + 置信度**，不能只写「无主/未确认」。
- 命名卷、非 DB 匿名卷、非批次日单例一律「需决策」或「不清理」，不得仅凭名字/年龄判死。

### 4. 基础设施 / 安全边界表（必给）

| 项 | 结果 |
|---|---|
| 容器重启 | 0 |
| 引用对象完好 | N/N |
| 未读取凭据 / 未连远端 / 未停容器 / 未 prune | 逐项确认 |
| 执行失败 / 跳过 | 0 / 0 |

### 5. 下一步表

| 待办 | 对象 | 责任方 | 到期/触发 |
|---|---|---|---|

### 无对象分类的复盘任务（如每周容量）

同样用表格，列固定为：**项目 | 本轮值 | 上轮/基线 | 变化 | 说明**。
盘面、每日任务健康、增长证据、建议各一张表；结论汇总行不变。

## 落盘与记账

- 本轮目录：`/data/metrics/ai-storage-maintenance/<YYYY-MM-DD>-<task>/`，附采集时间、范围、证据、逐项保留原因。
- 机器可读：`report.json` / `summary.json` / `evidence.json`（按任务取用）+ `raw/`（原始证据）；
  **不产出 HTML**。
- 账本：`/data/code/mole-linux/storage-audit.log` 追加一节，含日期、证据命令、逐项证据与结果、回收字节、遗留项。
- 回复末尾给出上述路径的 Markdown 链接。

## 反例（不允许）

- 用大段散文代替表格描述「清了多少、哪些没清」。
- 只写「待确认」而不给来源项目、证据、置信度或下一步。
- 把容器环境变量、密钥、token、数据库行内容写进任何表格或证据文件。
- 为凑表格行数而放宽清理门槛；数字与明细对不上。
